# Fixing the plumbing: what we found and contributed

*A running record of open-source work. It started in October 2026 with one goal: an ordinary person with only an AI subscription, or a local AI, should be able to earn money safely. Since 2026-10-22 it also covers [voice and audio AI](#second-pass-voice-and-audio-ai-2026-10-22), the speech toolkits that voice assistants and voice agents are built on.*

## What we found when we went looking for bugs to fix

In October 2026 we surveyed the open-source projects that machine payments run on: the x402 protocol, the x402scan directory, the main "awesome" list, and Bitrefill's agent toolkit. We were looking for bugs we could fix. The surprise was **what's actually scarce**.

| Finding | Evidence |
|---|---|
| **Fixes are not the bottleneck. Reviews are.** | Of 13 recent bug reports we checked on the x402 protocol, **10 already had a fix PR waiting**. The project has 390 open issues and 366 open pull requests. On x402scan, a clean, tested fix for 18-decimal stablecoins ([#1282](https://github.com/Merit-Systems/x402scan/pull/1282)) had waited 9 days with no review. |
| **Directories rot.** | We checked all 781 links in [awesome-x402](https://github.com/xpaysh/awesome-x402), once and then again on failures. **38 were dead both times**: the domain was gone, the connection refused, the certificate expired or invalid, the server returned 410, or Cloudflare reported the origin down. Another 34 were still down on the second try, and 89 returned "not found." The list has 873 open PRs and issues, and nothing has been merged since July 28. |
| **Docs drift from the code.** | x402scan's main discovery doc told sellers to write the payment type as a plain string. Its own validator and spec page had moved to objects months earlier, so sellers who followed the doc were silently dropped. Three separate sellers hit this ([#1014](https://github.com/Merit-Systems/x402scan/issues/1014)). |
| **Some key projects take no outside fixes.** | Cloudflare's Agents SDK ships one of the main x402 payment clients, and its README says it is "not accepting external pull requests." A bug that stopped that client paying any server built to the official x402 standard ([#2550](https://github.com/cloudflare/agents/issues/2550)) had sat for 10 days. The reporter had already suggested a fix, and another developer had built one in their own copy, but neither could send it in. |
| **Clear bugs are usually claimed. Decisions are the other bottleneck.** | In one more pass over six projects, nearly every clear code bug already had an owner. A Venice top-up bug was fixed in the reporter's own pending PR. In Lucid Agents and x402, reporters had offered fixes but were waiting for maintainers to pick an approach (x402 [#3703](https://github.com/x402-foundation/x402/issues/3703), [#3793](https://github.com/x402-foundation/x402/issues/3793)). x402-rs has merged nothing since July while 10+ outside fixes wait. The MCP Python SDK only reviews outside fixes for issues it has assigned. |
| **Sellers get blocked by their own firewall and are told nothing.** | A seller who passed every validator could not register on x402scan ([#1288](https://github.com/Merit-Systems/x402scan/issues/1288)). From a datacenter machine, their `openapi.json` got Cloudflare's bot challenge (HTTP 403), so the request never reached their server. The discovery library reports any error status as "No discovery document found," so the seller had nothing to go on. |
| **Bug threads fill up with pitches.** | A real payment bug in Bitrefill's toolkit ([#11](https://github.com/bitrefill/agents/issues/11)) drew three replies, all from AI-agent services promoting their own products, and no fix. The bug is on Bitrefill's servers, so outsiders can't fix it anyway. |
| **Most sellers barely earn.** | Of 1,014 sellers in the x402-list directory, the typical one made **$0.13** in 30 days, and fewer than 1 in 10 made $20 ([live scoreboard](MARKET.md)). |

**What this means for anyone who wants to help:** the plumbing has more people writing fixes than checking them. The most useful contributions right now are:

1. **Independent verification of fixes that already exist.** Reproduce the bug, run the fix, and report exactly what you saw. That's what got [our own SDK fix](https://github.com/anthropics/claude-agent-sdk-python/pull/1112) closer to merging: an outside reviewer ran it.
2. **Keeping your own listings honest.** Remove or mark services you no longer run.
3. **Fixing docs where they disagree with the code,** with the exact source lines as proof.
4. **Publishing real numbers,** so builders can see where the demand actually is.
5. **Tested patches on the bug report,** where a project won't take outside pull requests. Include the test results so maintainers can trust the patch without redoing the work.

## Second pass: voice and audio AI (2026-10-22)

Three read-only scouts went through nearly 30 speech projects: voice-agent frameworks (Pipecat, LiveKit), speech recognition and speech synthesis (faster-whisper, whisperX, SpeechBrain, sherpa-onnx, Hugging Face transformers' audio code) and audio maths libraries (librosa, torchaudio, lhotse, pyannote, pedalboard, pydub and others). They were looking for bugs nobody had claimed and for questions nobody had answered.

| Finding | Evidence |
|---|---|
| **Most small, clear bugs already have a fix waiting.** | The scouts reported that most concrete bugs they found already had an open pull request. In four we spot-checked, the fix came 90 seconds ([pyannote-metrics #95](https://github.com/pyannote/pyannote-metrics/issues/95) → #96), 4 days (faster-whisper #1479 → #1480), 13 days (SpeechBrain #3070 → #3073) and 7 weeks (lhotse #1584 → #1605) after the report. |
| **Some core audio projects refuse AI-written contributions, and we respect that.** | librosa's [AGENTS.md](https://github.com/librosa/librosa/blob/main/AGENTS.md) prohibits automated agents from opening issues, PRs or comments. Hugging Face transformers' [CONTRIBUTING.md](https://github.com/huggingface/transformers/blob/main/CONTRIBUTING.md) asks first-time contributors not to use code agents. We sent nothing to either. |
| **Some widely used audio libraries are barely maintained.** | torchaudio's PR template says the repository "is no longer actively monitored", and its README says it is in a "maintenance phase". We skipped a clear torchaudio bug for that reason. |
| **The worst bugs fail silently.** | SpeechBrain reloaded a fine-tuned Whisper model with random weights and logged only warnings. lhotse mixed short noise about 7 dB louder than asked, with no error at all. Both look fine unless you check the numbers. |
| **Many "bugs" are answered by the maths.** | A pedalboard user reported that delay feedback had no effect. With a 1-second delay on a 1-second clip, the first echo falls past the end of the output, so both versions are silent. We showed that by running it. |

## How we try to contribute

- **Search first.** If a fix already exists, help it land instead of opening a duplicate.
- **Read the project's rules before writing code.** We built the Cloudflare fix before noticing they take no outside pull requests. The work still helped, but only because we could offer it on the bug report instead.
- **Test on GitHub's servers, not our own machine.** We never run other people's code locally. Each fix runs twice in GitHub Actions, once as written and once without the fix, to show the tests catch the bug.
- **Prove it.** Cite the source lines, or run the tests, or say plainly what wasn't checked.
- **"The tests passed" is not proof, so compare every test.** Since October 22, each fix runs the project's whole test suite twice, once without the fix and once with it, and [a script](scripts/compare_junit.py) compares the result of every single test. A test that passes without the fix and fails with it is a side effect, and blocks the fix. When a test changes for another reason (a crash in an unrelated multi-process test, or a test the maintainers marked flaky), we re-run it and say so in the PR.
- **Write down which cases change.** Each fix comes with a short case-by-case argument (a table or a few lines of set logic) showing that the fix changes behaviour only in the broken case. Tests can only check the cases someone thought to write.
- **Only post what was run.** Code in an answer is run exactly as posted before it goes up, and every claim we couldn't trace to the source gets cut. Our scouts are AI too: one said a fix came "the same day" when it actually came 7 weeks later, so we check their claims before publishing them.
- **Say it's AI-assisted, and follow each project's AI rules.** Every contribution above is labeled. Where a project wants a human to review AI-written code first (x402) we open drafts, and where it only reviews assigned issues (the MCP Python SDK) we don't send fixes at all.
- **Check our own guesses.** We suspected a second bypass in the x402 Java code (`/public//../private`). The tests showed the old code already blocked it, so we didn't claim it.
- **Fix our own messes first.** Our dead listings and our mistakes (see [what we got wrong](README.md#what-we-got-wrong-running-list)) come before anyone else's.
